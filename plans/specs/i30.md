# i30 spec: Team socials unlock board + credit

**Goal.** Every exec earns credit for finished tasks, initiatives they led to Done, and ideas that get approved or picked; all credit adds to one team total, and each low-facility team social unlocks when that total crosses its line.

**Design choice.** No new database. Credit lives on the rows that already exist (Tasks, Initiatives, Brainstorm) and rolls up to Team Directory. The four socials are Initiatives rows (Type `Internal`), because a social is a dated slot that needs the Rubric form, a budget line and an owner, and Initiatives already computes `SU request due` and `SU status`. A separate table would duplicate all of that and break the house rule.

Schema checked 25 Sep 2026. Facts that shaped this: Brainstorm has no person-to-Directory link for the proposer (only `Created by`, a person field), so a relation is added. `Tasks done` on Directory is a percent, not a count. All 57 Done tasks today have no `Assignee (Directory)`, so the team starts near 0. 15 Directory rows are not Alumni or Offboarding.

## 1. Properties to add (build in this order)

**Tasks** (`49cca9bc-...`)
- `Credit` · formula (number). One per finished task, this term only.
```
lets(d, if(empty(prop("Scheduled")), prop("Date"), prop("Scheduled")), if(prop("Status") == "Done" and dateBetween(d, parseDate("2026-09-01"), "days") >= 0, 1, 0))
```

**Initiatives** (`7b98e159-...`)
- `Lead credit` · formula (number). Three for the owner when an initiative reaches Done this term.
```
if(prop("Status") == "Done" and !empty(prop("Date")) and dateBetween(dateStart(prop("Date")), parseDate("2026-09-01"), "days") >= 0, 3, 0)
```
- `Credit needed` · number (integer). Only set on unlock rows.
- `Crew` · relation to Team Directory, two-way; Directory side named `Socials crew`. Description: "Who this social is for. On unlock rows, every current exec."
- `Team credit` · rollup: `Crew` → `Credit` (Directory), Sum.
- `Unlock` · formula (text):
```
if(empty(prop("Credit needed")), "", lets(have, prop("Team credit"), need, prop("Credit needed"), filled, min(10, floor(have / need * 10)), if(have >= need, "🔓 Unlocked · " + format(have) + "/" + format(need), repeat("▓", filled) + repeat("░", 10 - filled) + " " + format(have) + "/" + format(need) + " · " + format(need - have) + " to go")))
```

**Brainstorm** (`177ac90c-...`)
- `Proposed by` · relation to Team Directory, two-way; Directory side named `Ideas proposed`. Description: "Who came up with it. Gets the credit."
- `Idea credit` · formula (number). Two when the idea is approved, assigned, done or picked for a slot.
```
if((["Approved", "Assigned", "Done"].includes(prop("Status")) or !empty(prop("Picked for"))) and dateBetween(prop("Posted on"), parseDate("2026-09-01"), "days") >= 0, 2, 0)
```

**Team Directory** (`197ac90c-...`)
- `Credit: tasks` · rollup: `Tasks owned` → `Credit`, Sum.
- `Credit: leads` · rollup: `Initiatives owned` → `Lead credit`, Sum.
- `Credit: ideas` · rollup: `Ideas proposed` → `Idea credit`, Sum.
- `Credit` · formula (number): `prop("Credit: tasks") + prop("Credit: leads") + prop("Credit: ideas")`

### Other problems found

- **Tasks `Credit` will over-count when old tasks get an assignee.** When `Scheduled` is empty, the formula falls back to `Date`, and `Date` on Tasks is last edited time. Any old Done task that gets edited this term then counts as credit this term. The spec's own note says the 57 Done tasks have no `Assignee (Directory)` yet. Filling that in will stamp them all as edited after 1 Sep and add up to 57 credits at once. Fix: fall back to `Due` instead of last edited, and give no credit when neither date exists:
  ```
  lets(d, if(empty(prop("Scheduled")), prop("Due"), prop("Scheduled")), if(prop("Status") == "Done" and !empty(d) and dateBetween(dateStart(d), parseDate("2026-09-01"), "days") >= 0, 1, 0))
  ```
  If `Scheduled` is not a date-type formula, replace `dateStart(d)` with `d`. Paste it into one Done task and read the result before saving.
- **Crew is a fixed list.** New hires don't join any unlock row on their own. Anyone hired later has to be added to Crew on all four rows by hand, or their credit won't count toward the team total.
- **A new linked view that i30 didn't ask for.** Club Dashboard, VP only section: "Upcoming slots: time left vs time needed" (https://app.notion.com/p/3e6ac90c76f1817eaeaae8e6362294d5). It's a view of Initiatives, not a new database, so no rule is broken. It isn't in the i30 spec or the Built notes; confirm which item added it.
