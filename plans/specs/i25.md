# i25 spec: Growth hub (Resources + required training per role + completion tracker)

**Goal.** One page where every exec sees the training their role requires, marks it done with proof, and the presidents see who is missing what; the same page doubles as the library for certificates, SU training and recorded BSA workshops.

Schema checked 25 Sep 2026 (read-only fetches of Team Directory, Semester Onboarding, Role History, SU Guides & Policies, Tutorials, Tasks, Handbooks, Help Center, Students' Union, Briefing). Facts that shaped this:
- Team Directory `Role` mixes team tags and status tags. Options, exact: `President`, `Finance`, `Events`, `Marketing`, `VP`, `Operations`, `Outreach`, `Photography`, `in Training`, `Leave of Absence`, `Creative`, `Technology`, `Alumni`, `Offboarding`, `Janitor`, `Co-op Term`.
- Team Directory has no Notion person property. The house pattern (Tasks, Briefing) is two fields: a person field that drives `me` filters and a Directory relation that drives rollups. This spec follows it.
- Semester Onboarding already tracks "Read the handbook" and "I accept the Agreement". Not duplicated here.
- SU Guides & Policies already holds rulebook summaries, e.g. `Conflict tools for execs` (the OHRCM deck), `Leadership expectations`, `Poster approval`, `Rubric: the SU's club portal`. Resources links to those rows; it does not copy them.
- A legacy `Tutorials` database (collection://d02ab8e7-355f-4800-915b-3bd5762a19e3, 15 rows, W26 SU modules) sits in Help Center. Left untouched. See "Safdar decides".
- The SU Clubs Training 2026-27 deck (Intro page) is marked "For Presidents and VP use only". Modules: A Intro, B Events, C Food, D Finance, E Club Management, F Human Resources, G Poster Policy, H Club Storage. Module F says every club member must use the SU Reporting Form for conduct, EDI and wellbeing concerns, so F applies to all execs.
- Intercultural Certificate: Laurier International, free, virtual on Zoom. **No delivery in Fall 2026.** Winter 2027 runs Thursdays 12 p.m., 60 min: 28 Jan, 4 Feb, 11 Feb, 25 Feb, 4 Mar, 11 Mar. Completion for the Laurier Experience Record = first session + last session + any two others. Source: https://students.wlu.ca/academics/global-engagement-and-exchanges/international-at-home/intercultural-certificate.html (fetched 25 Sep 2026).
- The Notion SQL query quota for this workspace is used up. Builder: read rows with `fetch` or `query-data-sources` in `rows` or `view` mode, not SQL.

## 0. Design choice

**Option (a): Resources DB + Completions join DB. Chosen.**

Why not (b), a `Completed resources` relation on Team Directory:
1. **"Missing" cannot be computed from (b).** A formula on a person can see what they completed, never what they did not, because Notion cannot list every Resource that matches a role without a relation to it. The only free-plan way to show "missing" is an assignment row per person per required item, created up front with Status `Assigned`. That row is the join table.
2. (b) stores no date, no proof and no verification. The Intercultural Certificate needs a screenshot; SU training repeats every year, so completion must be tied to a year.
3. The `My training` view needs a Notion person field on the row (`Exec = me`), the same way Briefing works. A relation on Team Directory cannot give that.

Cost: two new databases during the schema freeze (bsa-system.md section 2: "no new databases unless a VP asks for one by name until 8 Dec"). The tracker item is Safdar's and names a Resources DB, so this spec proceeds; Safdar confirms (see end). Nothing here duplicates Initiatives or Team Directory: Resources is a library, Completions is the person-by-resource join that Team Directory rolls up.

Formulas (Notion 2.0):

`Counts`
```
prop("Requirement") == "Required" and prop("Status") != "Excused"
```
`Required done`
```
prop("Requirement") == "Required" and prop("Status") == "Done"
```
`Required open`
```
prop("Requirement") == "Required" and prop("Status") == "Assigned"
```
`Overdue`
```
prop("Required open") and !empty(prop("Due")) and dateBetween(prop("Due"), today(), "days") < 0
```
`Open code`
```
if(prop("Required open"), prop("Code").join(", "), "")
```
If the API rejects `.join` on the rollup, use `if(prop("Required open"), format(prop("Code")), "")`.

## 4. Properties added to Resources (after Completions exists)

- `Completions` · dual of `Resource` (created in step 3).
- `Assigned` · rollup: `Completions` → `Counts`, Checked (count).
- `Done` · rollup: `Completions` → `Required done`, Checked (count).
- `Completion` · formula (text):
```
if(prop("Assigned") == 0, "", format(prop("Done")) + "/" + format(prop("Assigned")) + " done")
```

## 5. Properties added to Team Directory

Add only; rename or remove nothing.
- `Training records` · dual of Completions `Exec (Directory)` (created in step 3).
- `Training required` · rollup: `Training records` → `Counts`, Checked (count).
- `Training done` · rollup: `Training records` → `Required done`, Checked (count).
- `Training overdue` · rollup: `Training records` → `Overdue`, Checked (count).
- `Training open codes` · rollup: `Training records` → `Open code`, Show original.
- `Training` · formula (text). Description: "Required training done this year."
```
if(prop("Training required") == 0, "", format(prop("Training done")) + "/" + format(prop("Training required")) + " done" + if(prop("Training overdue") > 0, " · " + format(prop("Training overdue")) + " overdue", ""))
```
- `Certs missing` · formula (text). Description: "Codes of required training not yet done."
```
prop("Training open codes").filter(current != "").join(", ")
```

```
- Required rows are created for you each year from your Role. You only change Status, Completed on and Proof.

```
